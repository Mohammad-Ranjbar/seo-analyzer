# ADR-0002: Obsidian و drawDB

## زمینه و مسئله
مستندات باید دوزبانه، قابل نسخه‌بندی و بدون قفل‌شدن در سرویس پولی باشند و ERD نیز در مرورگر قابل ویرایش باشد.

## محرک‌ها
- هزینه صفر MVP
- فرمت باز و قابل نگهداری در Git
- کار آفلاین و مالکیت داده
- خروجی تصویری و قابل بازبینی

## گزینه‌ها
1. Markdown در Vault محلی Obsidian و drawDB رایگان
2. سرویس مستندات ابری پولی
3. فایل‌های Binary اختصاصی

## تصمیم
`docs/` یک Vault محلی سازگار با Obsidian است. هر سند فایل فارسی و انگلیسی مستقل دارد. ERD در drawDB ساخته می‌شود و فایل‌های منبع باز DBML و JSON آن در مخزن نگهداری می‌شوند. خروجی تصویری فقط زمانی ذخیره می‌شود که اندازه آن برای مخزن معقول باشد.

## پیامدهای مثبت
- مستندات بدون ابزار خاص نیز خوانا هستند.
- مالکیت و تاریخچه در مخزن می‌ماند.
- ابزارها قابل جایگزینی‌اند.

## پیامدهای منفی و ریسک‌ها
- Sync خودکار Obsidian وجود ندارد.
- فایل محلی drawDB باید پس از تغییرهای تأییدشده Export شود.
- خروجی تصویری مدل‌های بزرگ ممکن است بسیار حجیم باشد و نباید بدون کنترل اندازه وارد Git شود.
- ترجمه‌ها ممکن است از هم فاصله بگیرند.

## زمان بازبینی
در زمان اضافه‌شدن تیم یا نیاز واقعی به همکاری هم‌زمان.
