# PRD — Persian SEO Analyzer

## هدف

ساخت یک API امن و چندمستاجری برای تحلیل دوره‌ای SEO صفحات محصول و دسته‌بندی فروشگاه‌های فارسی و اندازه‌گیری پیشرفت نسبت به Baseline و رقبای تأییدشده.

## کاربران

- Owner و Admin سازمان
- Member سازمان
- مدیر Workspace
- عضو Workspace با Role سفارشی
- مشتری ماشینی از طریق API Key
- مدیر سیستم و پذیرش Waitlist

## جریان اصلی

1. کاربر با موبایل و رمز ثبت‌نام می‌کند.
2. Organization می‌سازد یا دعوت موبایل، ایمیل یا لینک را می‌پذیرد.
3. Workspace و Roleهای سفارشی می‌سازد.
4. SEO Project و Scope ساختاریافته را تعریف می‌کند.
5. دامنه اصلی و Propertyها را اضافه می‌کند.
6. رقبا را وارد می‌کند یا پیشنهاد می‌گیرد و آن‌ها را تأیید می‌کند.
7. Crawl دستی یا زمان‌بندی‌شده را اجرا می‌کند.
8. یافته‌ها، امتیازها و برنامه اقدام را می‌بیند.
9. وضعیت Taskها را تغییر می‌دهد.
10. Crawl بعدی Verification فنی و پیشرفت را ثبت می‌کند.

## نیازمندی‌های عملکردی

### هویت و عضویت

- ورود با موبایل و رمز یا OTP؛ OTP در توسعه Log می‌شود و در بتای عمومی تا اتصال SMS غیرفعال است.
- کاربر می‌تواند عضو چند Organization باشد.
- نقش سازمانی ثابت و نقش Workspace سفارشی است.
- دعوت با موبایل، ایمیل یا لینک محدود امکان‌پذیر است.

### Scope و Property

- URL سایت هنگام ساخت پروژه اختیاری است، اما برای Baseline ضروری است.
- هر پروژه یک دامنه اصلی و چند Property دارد.
- هر رقیب می‌تواند چند دامنه و Subdomain داشته باشد.
- رقیب پیشنهادی قبل از تأیید ذخیره تحلیلی یا Crawl نمی‌شود.

### Crawl

- رعایت robots.txt، User-Agent شفاف، Rate Limit، Backoff و سقف مدیریتی الزامی است.
- فقط Product و Category تحلیل می‌شوند.
- تشخیص نوع صفحه خودکار و قابل اصلاح است.
- HTML اولیه روش پیش‌فرض و Headless روش fallback است.
- Polling همیشه و Webhook امضاشده به‌صورت اختیاری در دسترس است.

### تحلیل و پیشرفت

- اولین Crawl موفق Baseline است.
- معیارها به‌صورت نسبت و امتیاز تفکیک‌شده گزارش می‌شوند.
- مقایسه MVP در سطح کلی سایت است، نه تطبیق محصول‌به‌محصول.
- فرمول Rule و Score نسخه‌دار است.
- وضعیت Task و Verification فنی مستقل‌اند.

### تولید SEO

- ورودی پایه: title، category و brand اختیاری.
- خروجی: SEO title، meta description، keywords و slug.
- محصول می‌تواند از API یا Crawl ایجاد شود.
- همه نسخه‌ها و تصمیم accepted/rejected/applied ذخیره می‌شوند.

### حذف و تاریخچه

- تاریخچه تا حذف کاربر نگهداری می‌شود.
- حذف ابتدا نرم و پس از مهلت قابل تنظیم قطعی است.
- HTML کامل ذخیره نمی‌شود.

## نیازمندی‌های غیرعملکردی

- جداسازی Tenant با Shared Schema و PostgreSQL RLS
- API versioning، DTO validation و OpenAPI
- کلیدها و Tokenها به‌صورت Hash یا رمزنگاری‌شده
- Queue برای Crawl و تحویل Webhook
- Idempotency برای عملیات تکرارپذیر
- Audit Log اقدامات مهم
- تست واحد، یکپارچه، E2E و تست منفی دسترسی بین Tenantها

## خارج از MVP

- پرداخت و Subscription
- تطبیق محصول‌به‌محصول با رقبا
- تحلیل مقاله و صفحات عمومی
- Search Console و رتبه واقعی کلمات
- Core Web Vitals میدانی
- داشبورد کامل برای کاربر غیر فنی
- Cron دلخواه

## موارد باز

- انتخاب ORM و migration tool
- انتخاب Queue و Cache implementation
- انتخاب مدل محلی یا قرارداد BYOK
- تعریف نهایی Catalog مربوط به Permissionها و Audit Ruleها
- تعیین مهلت Soft Delete
