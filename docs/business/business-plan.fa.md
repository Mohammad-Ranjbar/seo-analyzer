# طرح کسب‌وکار

## مسئله

فروشگاه‌های فارسی معمولاً نمی‌دانند کدام مشکلات محتوایی یا فنی بیشترین اثر را دارند، رقبا در چه بخش‌هایی بهتر عمل کرده‌اند و آیا تغییرات آن‌ها واقعاً باعث پیشرفت شده است. تولید دستی Title، Meta Description، Keywords و Slug نیز برای کاتالوگ‌های بزرگ کند و ناهماهنگ است.

## راه‌حل

یک API پروژه‌محور که Scope کسب‌وکار را ثبت می‌کند، سایت و رقبای تأییدشده را به‌صورت مسئولانه Crawl می‌کند، Baseline می‌سازد، تغییرات را اندازه می‌گیرد و برنامه اقدام قابل پیگیری ارائه می‌دهد. تولید اطلاعات SEO محصول نیز بخشی از MVP است.

## مشتری MVP

- تیم فنی فروشگاه‌های ایرانی
- توسعه‌دهندگان فروشگاه‌ها و افزونه‌ها
- شرکت‌های طراحی سایت
- آژانس‌های SEO دارای توان اتصال به API

فروشگاه‌های فاقد نیروی فنی در فاز بعد با داشبورد یا افزونه آماده هدف قرار می‌گیرند.

## ارزش پیشنهادی

- تحلیل فارسی و فروشگاه‌محور
- مقایسه با رقبایی که کاربر تأیید کرده است
- اندازه‌گیری پیشرفت نسبت به Baseline
- گزارش قابل توضیح به‌جای یک امتیاز مبهم
- برنامه اقدام اولویت‌بندی‌شده
- API پایدار و قابل اتصال
- هسته Rule-based مستقل از AI

## MVP

- Organization، Workspace و SEO Project
- فرم ساختاریافته Scope
- سایت اصلی، Subdomainها و چند Property برای هر رقیب
- Crawl دستی، هفتگی و ماهانه
- HTML-first همراه Headless fallback محدود
- تحلیل صفحات Product و Category
- تحلیل Metadata، Heading، Canonical، Indexability، Structured Data، تصاویر، لینک‌ها و Status Code
- Baseline، Snapshot، امتیازهای نسخه‌دار و مقایسه کلی با رقبا
- Action Item با وضعیت کاربر و Verification فنی مستقل
- تولید و تاریخچه Title، Meta، Keywords و Slug
- API Key محدود به Workspace، Permission و Project
- Polling و Webhook امضاشده
- تاریخچه قابل حذف و Audit Log اقدامات مهم

## هزینه MVP

هیچ ابزار SEO، SERP یا AI پولی استفاده نمی‌شود. تحلیل اصلی Rule-based است. AI فقط با مدل محلی یا API Key کاربر فعال می‌شود. این تصمیم هزینه ابزار خارجی را صفر می‌کند، اما مصرف CPU، حافظه و فضای ذخیره‌سازی را حذف نمی‌کند؛ بنابراین ورود کاربران از طریق Waitlist و تأیید مدیر است.

## مدل درآمدی آینده

هر پلن سهمیه پروژه، رقیب، صفحه، Crawl زمان‌بندی‌شده، تاریخچه و تولید AI خواهد داشت. مصرف اضافه با Credit محاسبه می‌شود. در MVP فقط Usage ثبت می‌شود و Payment یا Subscription وجود ندارد.

## معیار موفقیت

هدف رسیدن به ۱۰۰ کاربر آزمایشی فعال است. کاربر فعال باید پروژه تأییدشده ساخته، حداقل یک Crawl موفق اجرا کرده، برنامه اقدام را دیده و یک Crawl مجدد یا Schedule ایجاد کرده باشد.

## ریسک‌های اصلی

- هزینه زیرساخت Crawl و Headless rendering
- تشخیص اشتباه رقیب یا نوع صفحه
- فشار ناخواسته روی سایت مقصد
- امتیازدهی گمراه‌کننده
- وابستگی به AI یا سرویس خارجی
- رشد کنترل‌نشده Snapshotها

## شرط ادامه سرمایه‌گذاری

ادامه محصول زمانی توجیه دارد که کاربران بازگردند، اقدامات پیشنهادی را انجام دهند، Crawl بعدی پیشرفت قابل سنجش نشان دهد و بخشی از کاربران تمایل واقعی به پرداخت داشته باشند.
